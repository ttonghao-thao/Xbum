# 自动整理相册

2026-11-15 用户确认：上传后的内容由系统自动整理，首页三个入口进入独立相册；手动配置仅作可选覆盖。该决定替换原规格 F04/F05 中成长线必须先手动启用的前置条件。

根因：旧首页从每日播放列表找一个 scene_type，命中只打开单张，未命中「往年今日」打开整个照片库；旅行依赖 confirmed，成长依赖 growth_enabled。播放列表有数量限制、每张只有一个场景，不能作为完整相册目录。

当日实机复查又发现：仅查询 family 把上传者本人私密照片也排除在整理浏览外；VLM 输出字段可选并自动补默认值，导致不完整回答以 confidence=0 / other 记录为成功；旧任务没有输出契约升级补偿。修正后分别处理本人整理权限、严格模型契约和历史自动补处理，不能把“页面有入口”当作历史数据已经可用。

## 归类规则

| 相册 | 自动规则 | 人工覆盖 |
|---|---|---|
| 往年今日 | 按家庭时区解释可信 taken_at；包含往年同月同日及前后 3 天，同日与邻近日期并存；邻近标注「这几天」，按原年份分组；跨年不把昨日误称一年前 | 人工更正拍摄日期立即生效。未知时间与上传时间不充作拍摄日期 |
| 慢慢长大 | 从已有 VLM scene_tags/objects/visible_activity/caption 中识别儿童/婴幼儿画面；已登记家庭人物跨月记录，或有成长画面支撑的跨月相似人物候选也纳入；按拍摄年月排序，未知日期单列 | 人物可设 auto/include/exclude。存在 include 时严格采用指定人物集合；指定人物没有照片时保持空相册；exclude 关联照片不会因模型重跑重新纳入。可恢复 auto |
| 一起走过 | VLM travel/outing 及有对应内容支撑的自动事件；未知时间仍可作为候选，不编造活动日期或城市；有事件时按事件分组、内部按时间排序 | 锁定/确认事件类型优先；手动改为 daily/other 等立即排除，手动 travel/outing 纳入，不被模型重跑覆盖 |
| 最近的日子（2026-11-16） | 按可信拍摄日回顾所选日前 30 天（按日），或所选月份（按月）；未知日期不充作最近拍摄 | 更正拍摄日期后进入对应时段；可固定入口及本人代表照片 |

VLM 分类仅使用 confidence ≥ 0.5 的已有结构化结果；这是工程候选阈值，不是准确率保证。否定画面描述与 uncertainties 不作为儿童证据。自动人物候选不表示同一孩子的身份已经确认，不生成姓名、亲属关系或「第一次」。人脸分析保持默认关闭，自动成长内容不依赖开启人脸；已有人工照片人物标记可继续使用。

集合允许交叉：同一张成长出游照片可同时属于成长和旅行，专属相册不受今日精选数量限制。API 仅做数据库读与轻量筛选，模型仍通过单 Worker 的子进程异步运行；完成后首页/相册每 5 秒更新，推荐通过已有去抖任务更新。人工变更立即反映到相册，并触发推荐更新。

四个相册默认用于本人整理浏览：当前家庭的 family，加上上传者本人的 private；排除 hidden/deleted，每次读取重检。私密缩略图仍通过 photo_access 验证，不向其他成员、跨家庭或 display 会话开放。`scope=family` 可显式只读家庭共享集合，推荐引擎继续采用该集合。个人整理不自动修改 visibility，不把私密内容加入家庭轮播、共享故事或家庭检索。首页无家庭播放列表时可从本人可见相册取封面，链接个人相册，不用私密封面引导相框播放。

照片库可用左上角复选框多选，或「选中本页我的照片」选取本页；「加入家庭共享」显示明确确认，只有确认后才 POST 批量 share。每批最多 200 张，仅上传者本人可共享，删除照片不可共享；整批先校验再变更，并记录审计。分页清除选择，后续上传默认值不变。共享/日期修改触发事件与推荐去抖更新，复用有效 VLM；人脸仅在家庭已授权时补跑对应步骤。

## 双层详情（2026-11-15 确认，2026-11-16 已实现代码）

用户提供的苹果相册截图作为页面结构参考：上方为带封面及播放控制的回忆区域，下方直接展示对应图片网格。截图只作为交互参考，不从静态画面推断其编码、选片算法或自动播放触发方式；自动播放是用户对 Xbum 的明确要求。参考截图不复制进仓库。

往年今日、慢慢长大、一起走过，以及后续同类自动相册入口，均采用同一详情页上的上下两层：

| 区域 | 已确认的功能要求 | 细化设计 |
|---|---|---|
| 上方：回忆影片 | 系统自动组织该相册照片，提供自动播放；不要求先创建事件、手动生成故事或前往 `/display` | 大幅封面/播放画面、标题、播放/暂停与全屏控制；影片生成或准备期间明确显示状态，下方图片可继续浏览 |
| 下方：对应图片 | 直接展示同一相册的完整图片集合，支持进入单张详情 | 保留现有日期/事件分组及分页；影片若采用精选子集，明确区分“影片使用照片”与“相册全部照片”，不能只保留精选而丢掉完整集合 |

实现时必须遵守：

1. 上下两层使用相同相册类型、日期/人物/事件筛选及可见范围。播放序列只能从该集合中取材，不能使用全库或家庭每日播放列表补足；也不能只根据当前图片页生成而遗漏后续页候选。
2. 进入相册后提供自动播放体验，并允许暂停、继续和全屏。默认静音；浏览器拒绝媒体自动播放时保留明显的点击播放入口。用户暂停后不因后台刷新强制恢复；离开页面停止播放。上述为落实自动播放的交互细化，不据截图断言 Apple 的具体行为。
3. 往年今日沿用往年同日前后 3 天及实际年份；慢慢长大按可信时间组织，不将未确认儿童拼成同一个人的成长叙事；一起走过沿用旅行/出游候选与人工事件覆盖，不虚构城市或日期。
4. 本人 private 可参与本人登录后的相册影片；其他成员只看到对其有权限的集合与影片。封面、标题、照片计数、播放清单和任何视频衍生文件均需相同授权。此播放属于个人相册浏览，不改变现有家庭故事、搜索或 display 的 family-only 契约。
5. 相册内照片隐藏、删除、撤回共享或人工排除后，后续媒体读取及影片访问重检资格，过期影片/缓存必须失效；权限变化不能等后台重生成才生效。
6. 没有候选时上下两层均显示真实空态；只有一张时可展示单张回忆，不复制凑数。生成失败不阻断下方浏览，也不反复强制全量分析。无需模型的日期归集继续独立可用。

当前实现采用浏览器照片影片：后端从完整筛选相册生成受权清单，顶部连续播放照片并显示实际时间、理由、计数和播放控制，下方保留全部照片。无需等待 FFmpeg 或创建 Story；家庭 Story 访问规则不放宽。影片静音，无预编码视频文件或个人影片导出，家庭故事 MP4 为另一能力。

验收应覆盖：三个入口均同页显示两层并能播放；播放素材与相册一致且跨分页取材正确；自动播放被浏览器限制时可手动开始；暂停不被刷新打断；空/单张/处理中/失败状态；本人、其他成员、跨家庭与 display 隔离；撤回权限后的旧影片及播放清单失效。

`pages/Albums.tsx` 已通过 `components/AlbumPlayer.tsx` 同页呈现两层。顶部每 2 秒重校验，API 失败清空；暂停在普通刷新中保留，切换入口重新开始，页面转入后台暂停。图片影片没有有声媒体 autoplay 限制；全屏被拒绝时提示并保留页面内播放。当前源码与测试执行结果仍须分别看待，实际回归结果见 TEST_REPORT.md。

## 精选、年鉴与整理控制（2026-11-16）

四类入口支持固定，成长可选已确认人物与年/月分组；所选人物照片为空不回退其他儿童画面，里程碑仍来自人工确认。旅行展示事件分组与每日照片计数，未知时间单列。私人出游画面只参与本人主题相册，不生成全家可读的私人事件摘要。

`select_highlights` 复用已有质量分、重复组和日期覆盖，人工固定代表优先；只选代表，不删原图，不宣称表情或审美判断。相似整理页可比较候选组，只有本人可固定代表或拆组。个人推荐 never/less 作用于主动影片与精选，全部照片仍可主动浏览；家庭规则另外约束家庭精选与大屏。

智能集合 `/collections` 同样提供上方照片影片与下方集合，但采用创建者独有、素材仅 family 的授权，不沿用自动相册本人 private 范围。动态规则、人工加入/排除和已撤回素材的返回过滤见 API.md。

## 历史分析自动补偿

`VISION_CONTRACT_VERSION=2`：7 个原有 JSON 字段全部必填，caption 非空。Ollama 解码限制短数组和短描述；明确截断的结果和缺字段结果均失败，不补造置信度。模型权重版本与输出契约版本独立记录。

单 Worker 启动及每 60 秒扫描当前家庭未隐藏/未删除照片，按契约版本为旧结果、缺结果和历史失败补排 VLM。新上传与补偿采用相同 `photo:{id}:vlm:vision-{version}` 幂等键；已有在途任务和当前有效结果不重复入队。每个版本沿用有限重试，失败达到上限不会在每次扫描时重置尝试次数；页面显示失败数，任务页保留历史失败记录。暂停和 VLM 关闭时不补排。

分类规则本身是读取已有数据的轻量逻辑，修改日期窗口不需要重跑模型。本次升级改变的是模型输出完整性契约，因此旧版视觉结果自动补处理；无需重跑已经有效的 metadata/quality/embedding。完成后自动刷新分类与推荐；人工标题、日期、人物选择和锁定事件保持原值。

## 验证边界

分类/时间/覆盖回归使用合成图片及明确注入的结构化分析 fixture，覆盖异步模型→事件→相册→推荐的契约。浏览器使用独立数据库、真实 API/Worker；重模型关闭，验证入口、日期筛选、空态与人工覆盖。迁移对带人物/人脸/里程碑的旧 schema 副本升级，校验保留关联与原手动选择。
