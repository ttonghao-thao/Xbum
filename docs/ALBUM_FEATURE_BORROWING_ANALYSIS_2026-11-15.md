## 1. 结论与定位

Xbum 最值得借鉴的是：**完整的自动整理层次、可纠错的人物与事件组织、可解释的精选、组合搜索，以及从真实素材生成故事的闭环。** Mac mini 的主要价值是持续在本地积累和复用照片理解结果，让家庭照片越整理越好找、越容易回顾。

建议延续“家庭 AI 记忆相框”的核心，增强其背后的本地记忆组织能力：手机负责主动导入、确认和纠错；Mac mini 负责持久索引、异步分析和生成；浏览器相框消费已授权、已整理的结果。无需改成手机系统相册，也无需更换 FastAPI / SQLite WAL / 单 Worker / React 架构。

三家值得借鉴的侧重点如下。这里的优先级是对 Xbum 的产品判断，不是厂商算法或效果排名。

| 借鉴来源 | 可借鉴的产品方法 | 对 Xbum 的转化 |
|---|---|---|
| Apple | 日期、地点、人物、主题集合与回忆分别组织；推荐内容允许纠错和减少出现 | 建立“完整相册→精选→故事”的清晰层次，完善人物与情绪偏好控制 |
| 华为 | 事件/主题自动聚合；向用户解释生成条件与处理时机 | 让用户知道为什么归入、为何未生成、还缺什么；将手机充电规则改为 Mac 资源预算 |
| 小米 | 从搜索、分类卡片到挑图、成集和分享的连贯操作 | 将“找出这批照片→精选→保存集合/故事草稿”做成完整流程，最后由本人明确共享 |

Apple 的旅程按位置分组，日期精选与人物命名也分别有入口；推荐排除会作用于回忆、精选和小组件。[旅程](https://support.apple.com/zh-cn/guide/iphone/iph7cce5d7a2/27/ios/27)、[日期精选](https://support.apple.com/zh-tw/guide/iphone/iph0ea0234e0/27/ios/27)、[人物](https://support.apple.com/zh-cn/guide/iphone/iph9c7ee918c/27/ios/27)、[推荐控制](https://support.apple.com/zh-hans/guide/iphone/iph10a9dd2a1/ios)。华为公开了时刻聚合与生成条件；小米官方说明了分类卡片、照片电影及搜索挑图能力。[华为时刻](https://consumer.huawei.com/cn/support/content/zh-cn16076667/)、[生成条件](https://consumer.huawei.com/cn/support/content/zh-cn01061601/)、[小米云相册](https://i.mi.com/guide/zh-CN/gallery/view)、[小米系统相册能力](https://os.mi.com/)。

### 2.1 两个容易误判的现状

**“慢慢长大”能自动归集，不等于已确认人物成长故事自动可用。** 相册按儿童画面及跨月人物线索归集；`timeline(person_id)` 和 `create_draft(person_id)` 仍检查 `manually_confirmed/is_family/growth_enabled`。新体验应消除入口误解，保持自动整理无需先配置，同时保留具体姓名、亲属关系及里程碑的人工事实约束；不能直接删除所有人物校验。

**“本地 AI 成功”不等于分类或搜索足够准确。** 现有 TEST_REPORT 记录真实模型冒烟及历史照片补处理；这些是已有报告证据，本轮没有复跑。报告明确指出真实人脸正样本、人工标注准确率、长期偏好和真实大库全模型吞吐尚未验收。

## 3. 建议采用的产品层次

| 层次 | 用户理解 | 内容规则 |
|---|---|---|
| 原始图库 | 我导入和获授权查看的所有照片 | 保存原片、人工说明及来源；不因精选结果淘汰照片 |
| 自动相册/主题集合 | 符合某个条件的完整集合 | 可以重叠、分页、为空；不受每日精选数量限制 |
| 事件/旅程 | 一次活动及其时间片段 | 需要时间/地点/内容证据，允许用户合并拆分；主题相似不等于同一活动 |
| 精选 | 从一个集合中挑出的代表照片 | 有数量、质量和多样性约束；必须能切换“查看全部” |
| 故事 | 对选定真实素材的有序讲述 | 有封面、章节、说明、节奏和版本；更改故事不改原片 |
| 家庭播放 | 当前适合全家看到的内容 | 仅 family，重新授权、遵守家庭偏好及展示时段 |

例如，一张孩子在海边的照片可以同时属于“慢慢长大”“一起走过”和某年某月，也可能被某个旅行故事选中。删除故事或移出精选，不等于删除照片；减少推荐也不等于隐藏原片。

### 3.1 用户补充确认：上方自动播放，下方对应图片

往年今日、慢慢长大、一起走过等入口，进入后必须在**同一详情页面**呈现两层：上方自动组织该相册素材，形成可自动播放的回忆影片；下方直接展示该相册对应的完整图片集合。用户可观看影片，也可直接逐张浏览，不需要先手动生成故事或跳去家庭相框。

上方若使用精选照片，下方仍保留完整相册；两层采用同一筛选和授权范围，不能将顶部绑定家庭每日播放列表，也不能把当前分页当作整个相册。本人 private 可在本人的相册影片中播放，但不能进入其他成员或 display；个人相册影片与现有 family-only 共享故事分别处理授权。

这是基本相册详情体验，不能等到 A09 高级章节/文案生成全部实现后才提供。当前 `Albums.tsx` 尚无顶部播放区；具体交互、空态、播放限制和验收记录在[自动相册双层详情要求](AUTOMATIC_ALBUMS.md)。静态截图只提供布局参考，自动播放要求来自用户文字说明。

## 4. 可借鉴的详细功能描述

### A01 自动精选集与“最近的日子”

**用户功能：** 三个已确认自动相册详情采用上方自动播放、下方对应完整图片的同页结构，见 3.1。建议再增加近期日/月回顾和可固定的主题入口；新入口沿用双层结构，下方可提供精选/全部筛选，但不能取消完整集合。卡片显示实际日期、照片数量和整理状态。不同成员的卡片计数、封面和标题只由其可见内容生成。

**自动规则：** 按可信拍摄时间和家庭时区分组，未知日期单列；照片质量和多样性决定精选顺序，不决定是否存在于完整相册。跨日期补上传按拍摄日归档；上传日期不能冒充旅行日期。“往年今日”继续始终包含往年同日前后 3 天。

**实现承接：** 复用 `MemoryAlbums`、照片权限候选和现有推荐评分，提取必要的共享选片逻辑；不要复制一套独立推荐服务。固定入口需要保存用户配置，但不必立即持久化所有动态相册照片关系。

**验收：** 一天有 80 张，精选只取代表照片但“全部”仍为 80 张；没有候选时不回退所有照片；其他成员和 display 不得通过卡片计数/封面获知私密内容。主要是轻量索引和 UI 工作，不需要每次打开都调用模型。

### A02 旅行档案：总事件、每日章节、地点证据

**用户功能：** “一起走过”中，一次旅行形成总卡片，进入后按天展开景点、活动与照片；能改旅行起止、地点和标题，将误分的两天合并，或把同一天的两次活动拆开。只有出游内容但证据不足时保持“出游候选”。

**AI 增强：** 在现有时间/GPS/向量/人物线索上判断候选旅行的连续性，选择全景、人物、活动、细节等互补画面作为封面和章节代表。地点名称来自人工确认或经校验的离线地名数据；VLM 看到海滩不能直接写“三亚”。无需 GPS 也能形成内容候选，但不能显示虚构路线。

**实现承接：** 扩展已有 Event 与 `segments_json` 的表达和编辑能力，先改善当前相邻照片启发式造成的过度串联/拆散，不先引入图数据库。当前 `cluster_events` 仅处理 family；个人旅行档案若包含 private，需要独立的个人可见范围设计，不能把私密分析写进全家可读的事件摘要。

**验收：** 同地点不同年份不误合并；跨日旅行可连贯，时间未知明确标注；合并/拆分后重算保留人工结果；撤回一张共享照片后，封面、章节、摘要及导出资格一起更新。主要复用已有理解结果，复杂案例才入队做多图复核。

### A03 人物档案与“我们一起”的合照集合

**用户功能：** 人物页显示命名档案、代表照片、按年照片、待确认候选和纠错入口。用户可以确认“这是同一个人”“这不是此人”，将误拆簇合并、误合簇拆开。选两人可查看双方同框照片；选多人可明确选择“全部同框”或“任一人”。

**AI 增强：** 优先呈现值得确认的候选，而不是让用户给全部照片逐张打标签。系统可建议高频同框组合，不能据此推断夫妻、兄妹或亲子关系。家庭成员身份和关系沿用人工确认。

**实现承接：** 复用 Person、Face、现有合并/拆分/锁定操作。当前搜索使用 `Face.person_id.in_(named)` 得到并集；合照必须补上明确的集合交集语义。“全家”还需要用户确定参与集合，不能把任一已登记家庭成员出现称为全家福。人脸分析当前仅用于明确共享且授权的照片，不因个人自动相册可见 private 而扩大生物特征处理范围。

**验收：** A 单人照、B 单人照不能混入 A+B 同框集合；关系未经确认不生成称谓；改错后重跑不恢复错误标签；相似人物、儿童年龄变化和人脸授权撤回分别验证。算法质量需要授权正样本，现有零人脸合成图冒烟不能替代。

### A04 成长年鉴与跨年对照

**用户功能：** 自动成长相册继续无需配置；确认某个人物后，可查看该人物按月/年的成长精选、同季节对照和人工里程碑。某年没有照片就保留空缺，不补造照片或经历。用户可以把某张低画质但有纪念意义的照片固定为年度代表。

**AI 增强：** 在每个时段内兼顾人物清晰、活动变化与场景多样性；只在身份得到确认后构建同一人的跨年对照。年龄文字使用已登记生日和可信拍摄时间计算，不能由外貌推断精确年龄；“第一次上学”等必须来自人工记录。

**实现承接：** 复用成长规则、人物、Milestone、时间线和故事编辑器。区分“成长画面集合”“已确认人物档案”“家庭成长故事”三个入口；解决当前自动相册与需手动条件的时间线/故事之间的体验断点，保留 `auto/include/exclude` 优先规则。

**验收：** 两个孩子不因都出现儿童标签而拼成同一个人的年鉴；指定人物没有照片时为空；人工排除和固定代表在分析升级后不变。默认以已有向量和时间索引完成，不为做年度页面重新分析全库。

### A05 连拍选优与相似照片整理

**用户功能：** 一个入口区分“完全重复”“相似连拍”“主题相似”。连拍组默认展示推荐代表并允许展开全部、并排比较、更换代表；给出“更清晰、曝光较好、人物更完整”等有实际依据的理由。可批量选择移入回收站，但不自动删除。

**AI 增强：** 先复用 SHA/pHash/时间窗口和已有向量，缩小候选；再在小组内比较构图、遮挡和可见表情。闭眼/表情比较是新增模型能力，不能把当前 Laplacian 清晰度分数称为“最佳表情”。也不做换脸或表情替换。

**实现承接：** 扩展 `duplicate_group` 周边的分组呈现与代表选择；质量、哈希与视觉相似应保留独立依据。当前近重复以相近拍摄/上传时间筛选，对跨年翻拍、裁剪版或重新压缩版本不一定召回；补充索引后需重新验证，不能直接扩大删除建议。

**验收：** 相同背景但人物表情不同不能被当成完全重复；用户指定的纪念照片不能被低质量分淘汰；错误分组可拆开；所有建议先经过可见性过滤，不能向成员透露他人的私密重复项。

### A06 可解释的组合搜索与以图找图

**用户功能：** 输入“去年夏天，小明和妈妈在海边的合照”，先显示可编辑条件：时间、已确认人物、人物关系、场景、同框要求。搜索结果分别说明结构化命中和语义相似；不满足硬条件的不能用高向量相似度补进来。无结果时建议用户主动放宽某个条件。

**AI 增强：** 先建立可靠的结构化语义和同义词处理，再评估本地语言模型作为受约束的查询解析器；不能让生成文本直接变成任意 SQL。支持“排除截图”“两人同时出现”等组合条件，并可用当前照片的已有向量找相似画面。

**实现承接：** 复用 `search.py`、时间解析和 `text_embedding` 任务。当前任一关键词匹配、人物并集、少量词扩展需要升级；要区分“活动参与人”和“照片中同框的人”。以图检索已有图片向量通常无需新推理，引用图片及结果两侧均重新授权。

**权限边界：** 首先增强现有 family 搜索。若要支持“搜索我的 private 照片”，应作为明确的新增个人搜索能力设计：查询记录、缓存、结果计数、自动补全和后续草稿均绑定本人；不能直接替换家庭候选函数。本文不改变当前检索排除 private 的要求。

**验收：** 用多条件人工标注查询验证 Precision@K/Recall@K 和硬条件违反率；“全家”“夏天”“上次”有歧义时显示解释，不悄悄放宽。记录结构化首批结果与语义重排分别耗时，不能承诺已有单 Worker 能即时完成所有搜索。

### A07 本地 OCR 与图片文字查找

**用户功能：** 可搜索照片内的招牌、票面、书页、手写说明等文字；命中时高亮对应区域，查看原图核对，允许校正识别结果。文字结果与照片标题、AI 描述明确区分。

**AI 增强：** 新增专门的本地 OCR provider，保存文本、位置、语言及识别来源。低分辨率缩略图不足时按需读取较高清衍生图或局部区域。OCR 识别到“北京”只是画面文字，不自动成为拍摄地点；票面的日期也不直接覆盖 EXIF。

**实现承接：** 目前没有专用 OCR 管线或索引；应沿用单 Worker、版本化结果与有限重试。可评估 SQLite 本地全文索引，但中文分词和召回须单独验证，不能认为启用 FTS 就能解决中文搜索。

**验收：** 中文、英文、旋转、模糊、无文字图片分别验证误识别与漏识别；隐藏/删除/撤权后文本索引和缓存同步失效。家庭检索只索引其可展示范围；OCR 内容不能自动进入大屏文案。模型选择、许可和实际内存占用在实现前实测。

### A08 一句话成集与可保存的智能相册

**用户功能：** 输入“把去年我们去海边的照片整理成相册”，系统先显示条件与匹配照片，再提供“保存这批照片”或“保存规则、以后自动补充”。之后可命名、换封面、固定首页、人工增删，并生成精选或故事草稿。

**关键规则：** 静态集合固定当前素材；动态集合随新增分析更新，但人工加入/排除优先。重新命中模型标签不能撤销用户排除。集合本身不改变任何照片的 visibility；“创建相册”和“分享相册”必须是两个明确动作。

**实现承接：** 现有三个自动相册是专门规则，不是可保存查询的通用智能相册。先复用其候选权限、分页和理由，再新增最小集合定义及人工覆盖记录。若首版限定 family 应清楚显示范围；个人集合涉及 private 时需要连同标题、封面、分享与缓存完整设计权限。

**验收：** 保存动态规则后新增匹配照片自动进入；人工排除持续有效；删除集合不删原图；点“生成故事”只能从当前家庭共享资格照片生成，不将私密内容隐式公开。分享预览只能要求上传者确认自己的私密照片。

### A09 自动回忆卡片与有证据的故事编排

**用户功能：** 相册顶部自动影片是已确认的基础体验（见 3.1），无需先手动生成故事。在此基础上，建议为完整旅行、近期活动、往年片段或确认的成长主题生成回忆建议卡片，并提供短/中/长故事、换封面、删减章节、重新排序等高级编排。删除回忆不删除照片，并能禁止同一主题反复生成。

**AI 增强：** 在现有素材上依次完成选片、章节、排序、基于证据的文案。选片兼顾时间覆盖和画面多样性，不只是按清晰度排序。文本只使用可信日期、人工地点/人物/说明，以及明确标记为画面描述的模型输出；每段保存所依据的照片和事实来源。

**实现承接：** 保留当前安全的事实模板作为无模型/失败时的有效输出，继续如实标记生成来源。新增本地异步故事编排任务，复用现有 Story、StorySlide、版本控制、播放器和 FFmpeg；不要另建一套故事系统。生成故事建议和正式加入家庭播放分开控制。

**验收：** 200 张旅行照片应得到有代表性的短故事，而非机械截取前 N 张；不把“疑似生日蛋糕”写成“某人的生日”；无地点不命名城市；用户编辑后重新生成不能覆盖已锁内容。生成期间和导出下载前都重检素材权限，撤回共享不能只删图片而保留泄露事实的文字。

### A10 口述记忆成为可检索、可播放的家庭故事

**用户功能：** 家人对照片讲述背景，系统本地转写并允许校对；确认后的文字可在家庭搜索命中，并作为故事旁白或照片说明。播放时可以选择原声与字幕，允许单独删除音频或修改转写。

**AI 增强：** 可从已确认讲述中提出人物、事件或年代关联建议，但只有用户确认后才写入事实。不同成员的说法保留讲述者和来源，不让模型自行裁定矛盾，也不把声音特征用于未经授权的身份识别。

**实现承接：** 复用 AudioMemory 与 whisper.cpp；当前关联/校对已经存在，新增的是确认文本索引、事实关联及音轨编排。原声时长与照片页时长需要协调。音乐限用户有权使用的本地音轨，无音乐保持静音；不引入声音克隆。

**验收：** 未校对转写与确认内容区分；撤回关联照片共享或删除录音后，不再从搜索、旁白、旧导出暴露该内容；用真实授权家庭录音验证口音、噪音与专名，TTS 冒烟不能替代。该能力比泛化修图更符合家庭记忆定位。

### A11 人物、日期、地点与主题的推荐控制

**用户功能：** 除单张喜欢/不喜欢，还能对已确认人物、日期范围、明确地点或主题设置“减少推荐”“不再主动推荐”，可查看与恢复规则。原片仍保留，主动打开相册或搜索的行为与推荐排除分别定义。

**语义边界：** “隐藏照片”继续按现有规则排除自动相册、故事和检索；“不再推荐某人”只是推荐控制，不等于删除、撤回共享或禁止主动查找。自动回忆建议、首页精选和新播放列表都应一致遵守。

**实现承接：** 当前 `Feedback` 虽有 actor，但 `build_daily_playlist` 按家庭聚合最近反馈；不能直接宣称已有个人偏好体系。新增规则需要区分“仅影响我的建议”和“影响家庭大屏”，明确谁可调整家庭策略。人物候选不确定时不声称已彻底排除所有相关照片。

**验收：** A 的个人设置不悄悄改掉 B 的首页；家庭大屏排除规则不被某次新分析覆盖；已生成建议重新读时也更新；恢复规则不修改原图。主要是规则与索引工作，不需要大模型。

### A12 整理进度与“为什么没有生成”

**用户功能：** 相册空态明确区分无候选、排队分析、分析失败、模型关闭、拍摄时间缺失、身份未确认和当前范围无共享内容。照片说明“为何入选”，精选说明“为何选这张”，事件说明“哪些线索把它们归在一起”。

**工程增强：** 复用现有 pending/failed、任务与推荐理由，补上各层可解释状态。允许只重试失败步骤；升级只补齐过期能力，不要求重新上传。区分分析覆盖率与识别准确率，不能用“152/152 成功”表示全部分类正确。

**Mac 调度：** 显示可用的处理窗口与暂停原因；优先保障浏览、上传和用户查询，再安排历史补处理和大批量导出。现有查询编码 priority=20 已高于后台分析，但正在执行的长任务不会被自动抢占，应如实显示等待。

**验收：** 暂停、缺模型、旧结果升级、重启及达到重试上限各有明确状态；恢复不会重复全量分析；不显示未经测量的“还有几分钟完成”。这是增强所有 AI 功能可信度的基础。

### A13 宠物主题与命名档案

**用户功能：** 先按猫/狗等可见内容形成宠物主题相册；用户可手动命名自己的宠物、指定照片与封面。系统建议相似照片由用户确认，不把所有同品种宠物当成同一只。

**能力边界：** VLM 标签能支持“照片中有猫”的候选，不等于个体身份识别。现有 YuNet/SFace 是人脸方案，不能直接宣称支持宠物。自动宠物身份需额外 provider、授权样本和误合并评估。

**实现承接与验收：** 主题归类可复用 A01/A08；命名实体不应挤进现有亲属关系字段。验证两只相似宠物、同一宠物不同年龄及人工纠错保留。适合作为通用主题体系成熟后的扩展，不阻断人物/旅行/成长闭环。

### A14 视频、Live Photo 与素材增强的范围判断

**可借鉴方向：** 手机动态照片配对保存、视频关键帧、视频中动作片段搜索、从真实片段选入故事，能补全家庭记忆。视频需保留时间码，搜索结果直接跳到命中片段；Live Photo 需保留静态图与短视频的配对关系。

**当前差距：** 现有上传以图片解码为入口，数据模型以 Photo 为核心；FFmpeg 照片导出和音频上传均不代表已支持视频库。需要规划媒体类型、元数据、衍生图、Range 读取、配对、删除、授权与时间码索引，属于跨模块新增范围。

**本地实现方向：** 先容器解析、关键帧抽样和可选语音转写，再对候选片段做视觉分析；不能逐帧无差别运行 VLM。实际机型格式兼容与视频长任务资源预算需单独验收。

**编辑方向：** 裁切、旋转、曝光调整及谨慎的老照片去噪，可以作为保留原片的可回退衍生版本评估。生成式消除/扩图是额外能力，成本、失真和实机性能需验证；不纳入当前优先主线。自动换脸、视频扩散生成、深度伪造仍遵守原规格非目标，不因竞品存在而加入。

## 5. Mac mini 本地算力如何发挥作用

### 5.1 使用已有结果，按需要增加计算

| 工作 | 优先使用的输入 | 本地计算策略 | 不能混淆的边界 |
|---|---|---|---|
| 日期/主题集合、人物交集、推荐偏好 | 元数据、人工标记、现有分析 | SQLite + 轻量集合运算；必要时增量缓存 | 增加页面入口通常不需要更大模型 |
| 旅行、年鉴、精选 | 时间/GPS、质量、向量、确认人物 | 先规则与多样性重排，歧义候选再深分析 | 单图有 travel 标签不证明一整段真实旅行 |
| 连拍选优 | 已有重复组、较清晰的局部衍生图 | 小组内比较，不对全库两两调用 VLM | 现有质量分不等于人像表情评分 |
| OCR、复杂视觉内容 | 有必要的高分辨率图块 | 独立离线 provider，按能力版本补齐 | 不能靠 960 缩略图保证小字识别 |
| 自然语言解析、故事文案 | 已授权的结构化事实与候选素材 | 单 Worker 中的有界任务；严格输出与失败回退 | 现有 Qwen 图片 provider 不自动具备这些业务能力 |
| 口述、视频 | 录音、抽样关键帧、时间码 | 分段任务、可恢复、控制临时文件 | 现有图片吞吐不能用于预测视频吞吐 |

原生 macOS、Metal/MPS、API 不加载 torch、重模型单并发和子进程结束释放内存继续保留。现有模型配置可作为试验基线，不因需求增加就默认升级更大权重。新增 OCR/审美/文本模型应先评估能否复用现有能力，再测准确率、峰值内存和模型切换成本。

### 5.2 从手机后台条件转成桌面资源调度

Mac mini 无需“电量超过 50%且熄屏充电”才能整理。应根据实际资源决定何时领取新重任务：用户查询优先、后台补处理限速、允许配置繁忙/空闲时段、磁盘不足时暂停会产生大文件的工作。系统内存压力或温控信号若可可靠获取再接入；不可取得时提供明确的保守降级，不假装已有完整自适应调度。

不通过增加重模型并发追求速度。可研究在短生命周期子进程中处理有限小批次以降低加载成本，但必须测得收益、设置内存/时长上限，并保留及时释放和查询等待预算；这属于后续优化提案，不改变当前逐任务隔离契约。

### 5.3 历史照片是能力的一部分

扩展现有 `reconcile_vision` 思路，为新增能力分别管理结果版本、输入依赖和失败状态。规则变化只更新索引/集合；新增 OCR 只补 OCR；编码器更换才重建对应向量。有效质量、人工日期、标题、人物关联和锁定事件不重做。

动态集合、故事建议和搜索索引都要带足够的来源/版本信息，权限变化优先于异步重建：缓存尚未刷新时也必须在读取端拒绝过期内容。模型升级后不要求用户重新上传，也不以无差别全量跑模型掩盖契约问题。

### 5.4 性能和质量必须分别验证

项目文档记录的部署基线为 Apple M4 / 16GB，本轮未重新探测硬件或负载。现有 1000/3000 张基准关闭了重模型，不能据此估算新功能耗时；单张 VLM 冒烟也不能直接乘照片数当成真实批处理承诺。

后续记录至少包括：基础页面与查询 P50/P95、排队等待与实际推理分开耗时、各模型加载/释放、系统内存压力、失败重试、导出磁盘增长和连续运行情况。RSS、MPS driver allocation、Ollama 分配可能描述不同层次，不相加冒充统一内存峰值。

## 6. 必须贯穿所有新功能的权限与事实规则

| 内容/动作 | 延续的约束 |
|---|---|
| 本人自动相册 | 本人 private + 已授权 family；排除 hidden/deleted |
| 家庭搜索、家庭故事、家庭相框 | 继续仅使用合格 family；新增功能不能扩大现有契约 |
| 个人搜索、个人事件或个人故事提案 | 都属于需要单独定义的新增范围；封面、标题、计数、缓存、生成文本与媒体采用相同可见边界 |
| 个人自动相册顶部影片（已确认，待实现） | 属于本人相册浏览，与下方图片采用同一可见集合；不直接复用 family-only 故事权限，也不扩大共享范围 |
| 人脸处理 | 默认关闭；当前仅对授权且明确共享照片运行；人工姓名/关系优先 |
| AI 建议共享 | 只提供本人有权操作的候选；本人明确确认后才变更 visibility，不能自动公开 |
| 隐藏/删除/撤回 | 读时重检；索引、故事、字幕、录音引用及导出下载同步遵守，不仅过滤图片 URL |
| 人工修正 | 不被模型升级或动态规则覆盖；人工加入/排除、身份纠错、日期/地点均有明确优先级 |
| 本地/离线 | 下载模型可联网；运行推理无云端回退；外网断开可用不等于 API 失联可播旧缓存 |

不建议为新增能力直接迁移存储、引入云 API、默认扫描整个手机图库、默认读取系统联系人，或自动推断家/公司位置。现有浏览器显式选择导入仍是跨品牌入口；若增加 Mac 文件夹导入，也只能处理用户选定目录，默认 private，并单独明确授权范围。

## 7. 建议优先级与依赖

以下是新增增强建议的评估排序，不是已批准的开发排期，不把原全量规格改为 MVP。

| 顺序 | 建议内容 | 理由 | 主要依赖/成本 |
|---|---|---|---|
| 高 | A12 解释/进度；A01 完整集合与精选区分 | 直接提升已有能力的可理解性与可见价值 | 现有任务/相册/推荐；以规则和 UI 为主 |
| 高 | A03 同框与身份纠错；A04 成长年鉴；A02 旅行组织 | 紧贴家庭记忆定位，改善现有三个相册的深度 | 人工身份、日期/事件质量与权限边界；规则到中等模型成本 |
| 高 | A06 严格组合搜索；A05 连拍选优；A11 推荐控制 | 提升找图、选图和主动展示的可信度 | 结构化语义、质量依据、偏好作用范围 |
| 中高 | A08 一句话成集；A09 自动回忆编排 | 将零散能力连成可见产物 | 先有可靠筛选与选片；再添加有界本地生成 |
| 中高 | A10 口述故事；A07 OCR | 本地算力有明确增量价值，扩展照片可检索信息 | 新索引/音轨或 OCR provider、权限失效链 |
| 扩展 | A13 宠物身份、A14 视频/Live Photo/编辑 | 有价值但新增数据类型或模型边界大 | 独立格式、准确率和资源验收；不混入现有照片完成度 |

建议的工程里程碑：先建立范围一致的集合/解释/偏好基础；再补身份、旅行、成长与组合查询；之后连接精选、成集和故事；OCR、口述及视频按相应依赖接入。每个里程碑都应包含权限、人工覆盖和历史增量补齐验证，不能最后统一补安全边界。

## 8. 后续验收应如何衡量收益

| 方向 | 可执行的验证 | 不应代替它的证据 |
|---|---|---|
| 自动相册 | 合成日期/权限/覆盖契约；授权样本人工判定归类的误报漏报 | 页面出现入口、任务成功率 |
| 旅行/成长 | 标注事件边界、身份与年度覆盖，记录错误合并/拆分和纠正次数 | 自动生成若干相册数量 |
| 搜索 | 真实标注查询，人物交集/时间/否定条件；命中率、排序质量、硬约束违反率 | 向量维度正确、余弦计算能运行 |
| 选优 | 人工比较候选组，检查表情、构图、重复曝光及代表保留 | 清晰度分数升高 |
| 故事 | 每段事实可追溯、素材覆盖、近重复比例、用户需修改次数 | MP4 能播放、JSON 校验通过 |
| OCR/语音 | 授权样本的字符/专名错误、检索命中、人工校对负担 | 几何图或合成 TTS 的单例成功 |
| 隐私 | 两成员、两个家庭、display；原图/文本/计数/封面/导出/缓存逐层撤权验证 | 仅在前端隐藏按钮 |
| 实机 | Mac 连续批处理与交互共存，真实手机上传/录音、权限撤回、重启恢复、离线条件 | 本机小图吞吐或 fake provider 测试 |

先沿用规格要求建立至少 100 张经授权、人工标注的评估样本，并补充必要的跨年、无 EXIF、相似人物、连拍等切片；样本数量本身不保证覆盖多年成长和长旅行。真实素材留在本机受保护目录，仓库只记录匿名指标和复现方法。对确定性权限/人工覆盖约束要求测试无违规，对识别质量先测基线再确定可达目标。
